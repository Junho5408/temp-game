# 버그 티켓 처리 (개발)

`CLAUDE.md` 의 작업 규칙을 따른다 (규칙은 src/core 에만, 화면 코드와 섞지 않기, 결정은 PROGRESS.md 에 기록).

## 1. 고를 티켓
- 인자로 번호를 받으면 그것만. 없으면 `docs/qa/tickets/INDEX.md` 에서 상태가 "열림"인 티켓 전부.
- 순서: 치명 → 높음 → 보통 → 낮음, 같은 심각도는 번호순.
- **밸런스 티켓**은 게임 느낌을 바꾸므로, 고치기 전에 사용자에게 제안 수치를 보여 주고 승인받는다 (CLAUDE.md: 계획 먼저). 기능 버그는 바로 고쳐도 된다.
- 시작 전 사용자에게 처리할 목록을 한 줄로 알린다.

## 2. 티켓마다
1. 티켓의 재현 절차대로 **먼저 재현**한다. 재현이 안 되면 상태를 "재현 안 됨"으로 바꾸고 이유를 처리 기록에 적은 뒤 다음 티켓으로.
2. 규칙 버그면 **실패하는 테스트부터** `tests/` 에 추가 (Node 기본 테스트 러너, 확률은 `createBattle({ luck: false })`).
3. 원인을 고친다. 티켓의 "원인 추정"은 참고만 하고, 실제 원인을 확인한다.
4. 검증: `npm test` 전부 통과 + 화면이 관련되면 `node tools/qa/smoke.cjs --run=fix-<번호>` 로 관련 점검 통과 확인. 밸런스면 `node tools/qa/balance.mjs --n=400 --run=fix-<번호>` 로 전/후 수치 비교.
5. 티켓 갱신: 상태 "수정됨", 처리 기록에 `<커밋 해시> · 한 줄 설명 · 추가한 테스트`. `INDEX.md` 상태도 갱신.

## 3. 마무리
- 티켓 하나 또는 관련 티켓 묶음마다 커밋 (`Fix BUG-003: …`), 끝나면 푸시.
- 중요한 판단(밸런스 수치 변경, 규칙 해석)은 `docs/PROGRESS.md` 에 이유와 함께 기록.
- 사용자에게: 고친 티켓 / 재현 안 된 티켓 / 보류한 티켓(승인 필요한 밸런스 등)을 짧은 표로. 다시 확인하려면 `/qa quick`.
