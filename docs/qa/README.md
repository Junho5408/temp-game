# QA 체계

QA 에이전트들이 게임을 점검하고, 개발 쪽이 받아서 고칠 수 있도록 **파일로 주고받는다.**

```
/qa  (QA Manager = 메인 세션)
 ├─ qa-functional  ─┐
 ├─ qa-exploratory  ├─ 동시에 → qa-output/<run>/findings-*.md
 └─ qa-balance     ─┘
        ↓
 qa-bug-analyst   → qa-output/<run>/analysis.md   (재현·원인 위치)
        ↓
 qa-reporter      → docs/qa/reports/<run>.md + docs/qa/tickets/BUG-###.md
        ↓
/fix-bugs (개발) → 티켓 우선순위대로 수정 → 테스트 → 커밋 → 티켓 닫기
```

- `qa-output/` : 도구가 만든 원자료(스크린샷, JSON). git 에 올리지 않음
- `docs/qa/reports/` : 회차별 QA 보고서 (git 에 남김)
- `docs/qa/tickets/` : 버그 티켓 (git 에 남김, 상태가 바뀌면 같은 파일을 고침)
- 도구: `npm run qa:smoke` / `npm run qa:monkey -- --seed=3` / `npm run qa:balance -- --n=400` (모두 `--run=이름` 으로 결과 폴더 지정)

## 발견 사항 형식 (QA 에이전트 → 분석가)
`qa-output/<run>/findings-<역할>.md` 에 아래 블록을 발견마다 하나씩:

```
### F-<역할 머리글자>-<번호> · <한 줄 제목>
- 종류: 버그 | 멈춤 | 화면 | 밸런스 | 개선 제안
- 심각도(추정): 치명 | 높음 | 보통 | 낮음
- 재현: <시드·저장 상태·단계. 도구 명령이 있으면 그대로>
- 기대: …
- 실제: …
- 근거: <결과 JSON 경로, 스크린샷 경로, 로그 한 줄>
```

## 버그 티켓 형식 (QA Reporter → 개발)
파일: `docs/qa/tickets/BUG-###.md` (번호는 기존 티켓 다음 번호부터)

```
# BUG-### <한 줄 제목>
- 상태: 열림 | 수정됨 | 보류 | 재현 안 됨
- 심각도: 치명 | 높음 | 보통 | 낮음
- 분류: 기능 | 멈춤 | 화면 | 밸런스 | 저장
- 발견: <QA 회차 run 이름> · <발견 사항 ID>

## 증상
## 재현 절차
1. …
## 기대 / 실제
## 원인 추정
<파일:줄 — 분석가가 찾은 곳. 확실하지 않으면 "추정" 이라고 적음>
## 완료 조건
- <무엇이 되면 닫을 수 있는지. 가능하면 "이를 확인하는 테스트 추가" 포함>

## 처리 기록
<개발 쪽이 고친 뒤 커밋 해시와 한 줄 설명을 덧붙임>
```

## 심각도 기준
| 심각도 | 기준 |
|---|---|
| 치명 | 진행 불가(멈춤), 저장 손상, 오류로 화면이 깨짐 |
| 높음 | 규칙이 설명과 다르게 동작, 자원(은자·체력·물품)이 잘못 늘거나 줄어듦 |
| 보통 | 화면 표시 오류, 밸런스가 기준을 크게 벗어남 |
| 낮음 | 문구, 사소한 연출, 개선 제안 |
