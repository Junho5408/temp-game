# BUG-022 음량 설정 저장값이 깨져 있으면 소리 초기화가 중간에 실패함
- 상태: 수정됨
- 심각도: 낮음
- 분류: 저장
- 발견: qa-20261127-0035 · F-EX-02
- 관련: BUG-004 (깨진 저장 검증을 설정 저장에도 넓히는 것)

## 증상
음량 설정 저장(`temp-game.settings.v1`)에 숫자가 아닌 값이 있으면, 첫 클릭 때 오류가 나고 소리가 망가진 상태로 남습니다. 게임 진행은 계속됩니다.
- 게임 안의 조작으로는 이 상태가 생기지 않습니다. 저장소를 밖에서 고쳤을 때만 생깁니다. 그래서 심각도를 낮음으로 했습니다.
- 다만 너무 큰 값(예: 99)이면 매우 큰 소리가 날 수 있어서 함께 고치기를 권합니다.

## 재현 절차
1. localStorage `temp-game.settings.v1` 에 `{"music":"abc","sfx":"x"}` 를 넣습니다.
2. 새로고침합니다.
3. 화면을 아무 곳이나 클릭합니다. 오류 2건이 납니다.
- 도구: `node qa-output/qa-20261127-0035/extreme3.cjs --run=qa-20261127-0035 --only=sound` (결과의 `sound.broken`)

## 기대 / 실제
- 기대: 깨진 설정은 기본값(배경음 0.5, 효과음 0.7)으로 되돌리고, 범위를 벗어난 숫자는 0~1 로 자릅니다.
- 실제:
  - `"abc"`/`"x"`: `AudioParam ... non-finite`, `AudioNode connect ... Overload resolution failed` 오류가 납니다.
  - `null`/`null`: 오류는 없지만 0/0 이 되어 무음입니다.
  - `99`/`-5`: 슬라이더는 100/0 으로 보이지만 실제로는 99 를 그대로 써서 음악 gain 이 약 54 입니다.
  - `null`, `5`, `{{{`: 기본값으로 정상입니다.

## 원인 추정
- `src/ui/audio.js:7-12`: `Object.assign(settings, JSON.parse(...))` 가 타입·범위를 검사하지 않고 덮어씁니다.
- `src/ui/audio.js:38-55` `init()`: 42행에서 `ctx` 를 먼저 만든 뒤 46행 `musicBus.gain.value = settings.music * 0.55` 에서 예외가 납니다. `sfxBus`·`noiseBuf` 는 null 로 남는데, 39행 `if (ctx) return true` 때문에 다시 초기화하지 않습니다. 그 뒤 효과음마다 오류가 날 수 있습니다.
- `src/ui/audio.js:28-30` `getVolume()`: 검증 안 된 값을 그대로 돌려줍니다(main.js:481-482 슬라이더 표시).

## 완료 조건
- 설정을 불러올 때 music·sfx 마다 확인합니다. 유한한 숫자가 아니면 기본값을 쓰고, 숫자면 0~1 로 자릅니다(`setVolume` 과 같은 규칙).
- `init()` 이 중간에 실패해도 반쯤 초기화된 상태로 남지 않습니다. 예를 들어 버스를 모두 만든 뒤 `ctx` 를 확정하거나, 실패하면 `ctx` 를 되돌립니다.
- 설정 정리 함수를 따로 빼고 Node 테스트를 추가합니다. 입력과 기대값은 아래와 같습니다.
  - `"abc"` → 기본값
  - `null` → 기본값
  - `99` → 1
  - `-5` → 0
  - `undefined` → 기본값
- smoke 에 깨진 설정 3종(`"abc"`, `null`, `99/-5`)을 넣고, 클릭 뒤 pageerror 가 0 인지 확인합니다.
