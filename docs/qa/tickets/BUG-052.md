# BUG-052 저장의 계열 값이 `toString`·배열 등이면 검증을 통과하고 첫 보상에서 판이 사라짐
- 상태: 열림
- 심각도: 낮음
- 분류: 저장
- 발견: qa-20261127-1430 · F-EX-03
- 관련: BUG-029 (깨진 판 저장 검증, 수정됨)

## 증상
판 저장의 계열(cls)이 `"toString"`, `"constructor"`, `"__proto__"`, `["fist"]` 이면 저장 검증을 통과합니다.
- 이어하기는 되지만, 첫 전투에서 이기면 보상 무공 목록이 비어 오류가 납니다.
- 판이 지워지고 타이틀로 돌아갑니다(이번 생 소실).
- 저장을 손으로 고쳐야만 생기는 일입니다.

## 재현 절차
1. 아무 판 저장(`temp-game.run.v1`)에서 `"cls":"fist"` 를 `"cls":"toString"` 으로 바꿉니다.
2. 이어하기 → 전투에서 이깁니다.
3. 콘솔에 `TypeError: Cannot read properties of undefined (reading 'name')` (renderReward)이 찍히고 타이틀로 갑니다. 저장은 사라집니다.
- 스크립트: `node qa-output/qa-20261127-1430/clsproto.mjs` (네 경우 모두 `re-parse after reward: REJECTED`), 화면 `node qa-output/qa-20261127-1430/repro-cls-proto.cjs`, 스크린샷 `ex-cls-proto.png`

## 기대 / 실제
- 기대: 모르는 계열 값은 문자열 `ninja`·`null` 처럼 검증에서 되돌립니다. 판은 계속 이어집니다.
- 실제: 검증을 통과하고, 보상 단계에서 판이 사라집니다.

## 원인 추정
- `src/core/run.js:153` `classes?.[run.cls]` 는 일반 객체 조회입니다. 그래서 Object.prototype 의 이름(toString 등)이 "있음"으로 나옵니다. 배열 `['fist']` 는 문자열 'fist' 로 바뀌어 통과합니다.
- 2차 위치: `src/ui/screens.js:183` renderReward 가 빈 카드(undefined)를 생각하지 않습니다.

## 제안
- `typeof run.cls === 'string' && CLASS_IDS.includes(run.cls)` 로 검사합니다(`src/core/schools.js:4` CLASS_IDS). `Object.hasOwn` 을 써도 됩니다.
- 보상 생성(rollCards)에서 pickFromPool 이 빈 값을 주면 거르는 방어를 둡니다.
- BUG-051 과 같은 줄이므로 함께 고칩니다.
- 함께 정할 것: `maxHp: 1e12` 도 지금 통과합니다. 상한(예: 999)을 둘지 정합니다.

## 완료 조건
- parseRun 에 cls = `'toString'`/`'constructor'`/`'__proto__'`/`['fist']`/`123` 을 넣으면, 결과 cls 가 CLASS_IDS 안의 값이고 cardPool 이 비지 않습니다.
- 그 판으로 전투에서 이기면 보상 화면이 정상으로 뜹니다.
- 이를 확인하는 테스트를 추가합니다.
