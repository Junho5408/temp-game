# BUG-029 깨진 판 저장(체력 0, 최대 체력 초과, 없는 위치 등)이 검증을 통과함
- 상태: 열림
- 심각도: 낮음
- 분류: 저장
- 발견: qa-20261127-0536 · F-EX-05
- 관련: BUG-004(수정됨) 후속

## 증상
판 저장(`temp-game.run.v1`)의 값이 말이 안 돼도 이어하기가 됩니다.
- `hp: 0`: 체력 0 으로 전투가 시작되고, 카드를 한 장 쓰는 순간 패배합니다.
- `hp: 999`(최대 70): 그대로 받아들입니다.
- `position: '99-9'`, 객잔 항목이 깨짐, `encounter.scale: null`: 이어하기 순간 "판 진행 오류" 가 납니다. BUG-004 의 안전망이 "저장 손상" 배너를 띄우고 판을 지우므로 멈춤은 없습니다.
- 저장을 손으로 고쳐야만 생깁니다. 회귀 기록(meta)은 깨진 값 7종 모두 안전하게 복구됐습니다.

## 재현 절차
1. `node qa-output/qa-20261127-0536/repro-analyst.mjs` (parseRun 만 확인)
2. 화면: `node qa-output/qa-20261127-0536/ex-saves.cjs` (사례 20개), `ex-hp0.cjs`
- 결과: `ex-saves.json` 의 `run:hp0Map`, `run:hpOverMax`, `run:badPosition`, `run:shopJunk`, `run:encounterBadScale`

## 기대 / 실제
- 기대: 말이 안 되는 값은 parseRun 이 고치거나 null 을 돌려줍니다.
- 실제: hp 0·hp 999·없는 position 이 통과합니다. 객잔·encounter 는 모양만 확인합니다.

## 원인 추정
- `src/core/run.js:117` `finiteNum` 은 0 을 허용합니다.
- `run.js:127` 은 `hp <= maxHp` 를 확인하지 않습니다.
- `run.js:140-147` 단계별 확인에서:
- map 단계는 position 이 지도 노드인지 보지 않습니다(`src/ui/screens.js:120` 에서 오류).
- shop 은 items 가 배열인지만 봅니다.
- battle 은 `encounter.scale` 을 보지 않습니다.

## 완료 조건
- parseRun 이 다음을 처리합니다.
- defeat 가 아닌 단계는 hp ≥ 1 이어야 합니다. 아니면 null 을 돌려줍니다.
- hp 가 maxHp 보다 크면 maxHp 로 낮춥니다.
- position 은 null 이거나 지도 노드 id 여야 합니다.
- shop 항목은 각각 있는 카드/물품 id 여야 합니다.
- battle 단계는 `encounter.scale` 의 hp·strength 가 숫자여야 합니다.
- 이를 확인하는 테스트를 추가합니다. `tests/run.test.js` 의 BUG-004 표 테스트에 hp 0(map), hp 999, position '99-9', shop.items 깨짐, encounter.scale null 을 넣고, null 이 나오거나 값이 고쳐지는지 봅니다.
