# BUG-004 깨진 저장을 이어하면 화면이 멈춤 (회귀 기록 숫자 검증 포함)
- 상태: 수정됨
- 심각도: 높음
- 분류: 멈춤
- 발견: qa-20261126-0921 · F-EX-03, F-EX-09

## 증상
판 저장에 모르는 물품·보물 id 가 있거나 꼭 필요한 값이 빠지면, 이어하기를 눌렀을 때 화면이 흐린 배경만 남고 멈춥니다. 새로고침해도 같은 일이 반복됩니다. 빠져나가는 방법은 "이 생을 버리고" 뿐입니다.
정상 플레이로는 생기지 않습니다. 위험한 때는 **아이템·보물 id 를 바꾸는 업데이트 뒤** 옛 저장을 불러올 때입니다.

같은 원인으로 회귀 기록(meta)의 숫자도 검사하지 않습니다 (F-EX-09). `runs:"abc"` 이면 타이틀에 "abc번째 생" 이 보입니다. 이때 기억 슬롯 수가 NaN 이 되어 기억 무공 개수 제한도 풀립니다.

## 재현 절차
1. `createRun()` 으로 만든 판을 serializeRun 한 뒤 아래 중 하나로 바꿔 `temp-game.run.v1` 에 넣습니다.
   - `bag:['nope']` → 오류 `reading 'name'` (main.js:404)
   - `treasures:['nope']` → 오류 `reading 'kind'` (main.js:400–401)
   - `phase:'battle', encounter:null` → 오류 `reading 'enemyId'` (main.js:265)
   - `cluesFound` 없음 → 오류 `not iterable` (main.js:241)
   - `zone:9` → 타이틀에 "undefined" (main.js:135), 배경 그림 오류 (main.js:228–230)
2. 새로고침하고 이어하기를 누릅니다.
3. meta 는 `{"version":1,"prologueDone":true,"runs":"abc"}` 로 넣고 새로고침합니다.
- 도구로 재현: `node qa-output/qa-20261126-0921/extreme.cjs --run=qa-20261126-0921 --only=brokenSaves`
- 규칙 쪽 확인: `node qa-output/qa-20261126-0921/repro-analyst.mjs`

## 기대 / 실제
- 기대: 깨진 판 저장은 불러오기에서 걸러져서 이어하기가 안 보이거나 버린 판으로 처리됩니다. 숫자가 아닌 meta 값은 기본값으로 바뀝니다.
- 실제: 다섯 가지 깨진 저장이 모두 불러오기를 통과해서(`parseRun -> accepted`) 화면이 멈춥니다. meta 는 "abc번째 생" 이 표시되고 슬롯 수는 NaN 입니다.

## 원인 추정
- `src/core/run.js:97–108` `parseRun`: 판 버전, 덱 카드 id, 지도가 있는지만 확인합니다.
- `src/core/meta.js:30` `parseMeta`: 타입 확인 없이 덮어씁니다. 31–33행은 일부 배열만 보정합니다.
- `src/core/meta.js:45–47` `memorySlots`, `:94` `validateLoadout`: NaN 을 막지 않습니다.

## 완료 조건
- parseRun 이 다음을 확인하고, 어긋나면 null 을 돌려줍니다 (모르는 물품·보물 id 는 버려도 됩니다).
  - `bag`, `treasures`, `cluesFound`, `visited` 배열이 있는지
  - 물품·보물 id 가 목록에 있는지
  - zone 이 범위 안의 정수인지
  - hp, maxHp, gold 가 숫자인지
  - 단계별로 필요한 데이터가 있는지 (battle→적 id, event→기연 id 등)
- parseMeta 는 숫자 필드(runs, deaths, bestFloor, clears.*)가 음이 아닌 정수가 아니면 기본값으로 바꿉니다. 배열과 met 도 정리합니다.
- memorySlots 와 validateLoadout 은 NaN 을 막습니다.
- 안전망을 둡니다: `show()`(main.js:251)에서 첫 오류가 나면 "저장이 손상되어 이 생을 끝냅니다" 를 보여 주고 판 저장을 지웁니다.
- 테스트 추가: `tests/run.test.js` 에 표 형태 테스트를 넣습니다. 위 다섯 가지 손상과 정상 저장의 parseRun 결과를 확인하고, 모르는 행낭 id 가 걸러지는지도 봅니다.
- parseMeta 테스트도 추가합니다: `runs:"abc"`, `deaths:-1`, `clues:null`, `met:{a:"x"}` 가 기본값으로 정리되는지 확인합니다.
