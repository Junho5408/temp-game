# BUG-021 음량 창이 열려 있어도 숫자키·E 로 카드 사용·턴 종료가 됨
- 상태: 수정됨
- 심각도: 낮음
- 분류: 기능
- 발견: qa-20261127-0035 · F-EX-03
- 관련: BUG-020 (원인이 같은 계열이라 함께 고치기를 권함), BUG-006

## 증상
전투 중에 音 버튼으로 음량 창을 연 채 키보드 `1` 을 누르면 첫 카드가 나갑니다. 덱 창(BUG-006)에서는 막혔던 입력이 음량 창에서는 막히지 않습니다.

## 재현 절차
1. 전투 중에 위쪽 막대의 "音" 버튼을 눌러 음량 창을 엽니다.
2. 키보드 `1` 을 누릅니다.
3. 내공 3→2, 손패 5→4 가 됩니다.
- 도구: `node qa-output/qa-20261127-0035/extreme3.cjs --run=qa-20261127-0035 --only=sound` (결과의 `sound.afterKey`)

## 기대 / 실제
- 기대: 음량 창이 떠 있는 동안 숫자키·E·Enter 로 카드가 나가거나 턴이 넘어가지 않습니다.
- 실제: 창이 열린 상태(`panelOpen: true`)에서도 카드가 나갑니다.

## 원인 추정
- `src/main.js:782-784` 의 `inputBlocked()` 는 `#deck-modal`·`#dialogue`·`#panel`·`#flow` 만 봅니다. 4-A 단계에서 생긴 `#sound-panel`(index.html:56)이 빠져 있습니다.

## 완료 조건
- 음량 창이 열려 있으면 전투 키 입력(1~9, E, Enter)이 막힙니다. 슬라이더의 방향키 조절은 그대로 됩니다.
- Esc 로 음량 창도 닫힙니다(덱 창과 같게).
- 권장: BUG-020 에서 만드는 "떠 있는 창 목록"을 `inputBlocked()` 가 쓰게 해서, 나중에 창이 추가돼도 같은 실수가 없게 합니다.
- smoke 의 BUG-006 확인과 같은 방식으로 "음량 창 열림 + 1/E" 확인을 추가합니다. 기대값은 손패·내공·턴이 그대로인 것입니다.
